# iPad 适配优化 · 0.5.1（12）

本轮从构建 11 的源码提交 `37c9521` 开始，针对 iPad 点击“加载农场”后导入方式显示不全的问题，扩展检查主页、追踪、工具、设置、11 个编辑板块、地图和辅助面板。

## 改动

- 导入方式改为有标题、取消按钮和滚动区域的独立大尺寸 sheet。关闭完成后再打开系统文件选择器，保留文件夹、原位双文件、复制导入和最近农场入口。
- 保存、放弃草稿、重载、备份恢复、动物批量操作、配方批量解锁和清空槽位使用系统 alert，避免将整个页面作为 iPad popover 的锚点。
- 主页面内容及标题使用一致的最大阅读宽度，编辑内容和保存操作区对齐。工具编辑入口按可用宽度分栏，在窄窗口和辅助功能字体下回到单列。
- 工具说明、标题和物品名称允许换行；辅助功能字体下分段选择器改为菜单，外观对比和成对指标改为纵排，外观编号网格随字号调整。
- 地图初始尺寸同时受可视宽度和高度约束，在横屏、竖屏切换后保留全图；放大后仍可双向滚动。关闭、复位和清空色值的点击区域至少为 44 点。
- 保留编辑页固定底部操作区的真实占位，避免盖住最后一行表单。

## 验证

当前本地已完成 66 个 Swift 文件的语法扫描和 6 项工程、版本、资源检查。语法扫描不等同 Swift 编译。

新增 7 项原生 UI 回归：导入选项旋转、三个文件选择器打开/取消/重开、11 个编辑页横屏、11 个编辑页竖屏、主页面和辅助面板、375 点内容宽度与辅助功能字号、地图默认全图和旋转。macOS 工作流分别选择可用的 iPad mini、大屏 iPad 和小屏 iPhone，并保留截图与测试摘要；iPhone 同时运行已有回归套件。原生结果待本轮运行结束后记录。

375 点模式是 Debug 的内容宽度夹具，不等同真实 iPadOS Split View 或 Stage Manager 操作；Release 不包含该夹具。原生测试使用合成数据，不导入或写入用户真实存档。真机分屏拖动、悬浮键盘、外接键盘和 VoiceOver 仍需实机验收。
