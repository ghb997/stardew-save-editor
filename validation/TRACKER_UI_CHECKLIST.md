# 追踪器原生界面验收清单

状态：**待在 macOS / iOS Simulator 上执行与人工验收**。本清单与截图脚本已准备，不代表新版 SwiftUI 已编译、运行或通过视觉验收。旧版 build 8 的 IPA 成功记录不适用于这次 UI 修改。

## 自动获取真实界面截图

在装有完整 Xcode 16+、可用 iOS 17+ iPhone Simulator 的 Mac 上，从项目根目录执行：

```bash
bash scripts/capture-tracker-ui.sh
```

脚本选取实际已安装的 iPhone 类型和兼容运行时，**新建一个干净的临时模拟器**，编译 Debug、安装并截图。退出（含失败和常规中断）会终止该 App、关闭并删除本次创建的临时模拟器。不会操作已有模拟器的数据，不导入或写入真实游戏存档，不删除源码、输入 App、构建记录或截图。强制杀进程/主机断电无法保证退出清理；仅在确认 `temporary-simulator-udid.txt` 所记设备由该次脚本创建后手动清理那个设备。

可以指定现有设备 UUID 作为**类型/运行时模板**，不是安装目标；其数据不会克隆：

```bash
SIMULATOR_UDID='<从 xcrun simctl list devices available 取得的 UUID>' \
  bash scripts/capture-tracker-ui.sh
```

也支持 `UDID` 别名。建议分别选一个最小支持尺寸 iPhone 和一个常用大屏 iPhone 的模板重复执行，验证自适应布局。UUID 必须是真实、可用、运行 iOS 17+ 的 iPhone。

若已有本次源码构建的 Debug Simulator `.app`，可跳过编译：

```bash
APPPATH='/absolute/path/Debug-iphonesimulator/SheaflightAmberVault.app' \
  bash scripts/capture-tracker-ui.sh
```

也支持 `APP_PATH`。不能传设备 IPA 或 Release App：Debug 启动参数在 Release 中不存在。脚本检查 Simulator 平台与 Debug 参数字符串；这不是二进制与源码完全一致的证明，复核时仍需记录构建来源。脚本会记录可执行文件 SHA-256。

默认结果保存在 `validation/tracker-ui/<时间>-<进程号>/`；可通过 `TRACKER_UI_OUTPUT_DIR` 更改父目录，每次仍创建独立结果目录，不覆盖上一次证据。`CAPTURE_WAIT_SECONDS=10` 可将每次启动后的截图等待由默认 5 秒增加至 10 秒（允许 1–30 秒）。这只是等待渲染，不是加载完成断言。

启动参数来自实际实现：`EditorStore` 中 `--ui-demo` / `--ui-demo-edits`，`RootView` 中 `--ui-tab tracker`，`TrackerView` 中本次新增的 Debug-only `--ui-tracker-section <SaveEditorSection.rawValue>`。详情参数仅与 `--ui-demo` 合用时生效，示例加载后打开指定追踪详情；它不等于交互点击已通过。示例农场为内存 XML 构造的“春风农场”，角色“小麦”，并未从 `/tmp` 读取存档。不要在示例会话点击写回/保存；此脚本不执行这些动作。

`--ui-screen progress`、`relationships` 等另一组参数打开的是**修改工具页面**，不是追踪详情。本脚本不用这一组参数，避免把编辑器截图冒称为追踪详情。外部提供旧版 Debug App 若缺少新的追踪详情参数，脚本会在截图前报错，要求重新构建当前源码。

## 人工交互验收

截图脚本会清理临时设备，因此后续交互请在 Xcode 自建的**专用测试模拟器**运行同一 Debug App，启动参数为 `--ui-demo --ui-tab tracker`；在 Xcode Scheme 的 Run > Arguments 中配置。不要选择存有真实游戏数据的模拟器。以下项目逐项记录“通过/失败/未测”、截图名和复现步骤，不自动勾选：

- [ ] 浅色、深色均没有启动失败、加载遮罩或系统权限弹窗掩盖结果。
- [ ] 总览、基础、收藏、农场生活、状态筛选可切换；选中态与内容一致，长胶囊可以横向滚动。
- [ ] 每个分组可展开/收起，箭头、触控范围、无障碍朗读与实际状态一致。
- [ ] 角色、外观、农舍、背包、进度、关系、技能、钱包、动物、配方、检查共 11 个现有模块都能从追踪器到达。
- [ ] 从靠后模块进入详情时，对应选中胶囊可见；横向切换后标题、内容、选中态同步。
- [ ] 详情逐项截图：角色、收藏进度、村民、技能、钱包、动物、配方、检查状态；返回和关闭后没有导航死路、重复标题或丢失底部导航。
- [ ] 追踪器的按钮只导航或筛选，不直接改变游戏数据；离开/返回追踪器后工具角标和待保存更改数量不应凭空变化。
- [ ] 示例数据可对照：第 2 年春 12 日、金币 28,640、累计收入 428,500；五项技能为 8/6/7/5/4。数字没有直接显示 `(...)` 插值表达式。
- [ ] 已出货/钓获/矿物/古物的**种类计数**与历史总数量明确区分；缺失统计显示未知/未记录而不是伪造为 0。
- [ ] 黄金核桃 27 表示当前持有余额，不显示为“已发现 27/130”；收藏分类计数之和不称为“完美度”或真实游戏完成率。
- [ ] 未保存示例更改（使用 `--ui-demo --ui-demo-edits --ui-tab tracker` 重启）有清楚提示；兼容性警告和未保存更改是不同状态，“无更改”不等于已完整验证存档。
- [ ] 钱包、配方、关系、背包、动物详情没有可点击但无效的空白卡片；空列表有说明，不崩溃。
- [ ] 在最小支持屏宽和最大辅助功能字号下滚动到页面底部，全部标签/尾部指标/关闭按钮可达，没有横向溢出、遮挡、错误截断。
- [ ] 横竖屏、屏幕旋转以及 iPad（如发布支持）不破坏布局；与底部系统 Tab Bar 无重叠，图标没有再次异常放大。
- [ ] VoiceOver 能读出模块名、计数/进度、展开状态和操作用途；完成状态不仅靠绿色区分。
- [ ] 分别关闭存档进入浅色/深色空状态，打开存档入口能导航到现有导入流程；本验收不要选择真实文件。
- [ ] 保存新源码的原生 build/test 结果及人工视觉结论。仅存在 PNG、语法扫描通过或旧 IPA 成功，均不能记为本次原生界面验收通过。

## 构建与测试是独立关卡

```bash
bash scripts/validate-on-macos.sh
```

现有验证脚本会构建并执行共享 Scheme 测试；它会使用/启动现有模拟器，并不采用本截图脚本的临时设备策略，运行前检查设备选择。现有 GitHub Actions `build-ipa.yml` 仅构建 Release arm64 未签名 IPA，不执行本清单、不产生追踪器截图、也不运行模拟器测试。

最终验收记录应包含：本次源码版本/摘要、Debug 可执行文件 SHA-256、Xcode 与 iOS 版本、设备与字号、原生编译/测试结果、16 张自动截图、补充的人工详情/滚动截图、参考对照结论、所有未测项与原因。尚无 Mac 或 iOS Simulator 时，结论必须保持“原生构建/运行/视觉验收受阻”，不能写成“通过”。
