# 穗光琥珀存档匣

一款个人使用的原生 iOS 17+《星露谷物语》1.6 存档编辑器。所有处理均在设备本地完成。

源码版本：`0.3.3`（构建 `8`）

本版完成存档安全、兼容性、编辑流程与游戏素材接入修改。详细变化见 [CHANGELOG.md](CHANGELOG.md)，素材来源见 [GAME_ASSET_PROVENANCE.md](GAME_ASSET_PROVENANCE.md)，验证范围与 Mac 验收步骤见 [VALIDATION.md](VALIDATION.md)。0.3.3 build 7 已由 [GitHub Actions](https://github.com/ghb997/stardew-save-editor/actions/runs/34190220247) 使用 Xcode 16.4 完成 Release、arm64、iPhoneOS 编译；尚未运行 XCTest、模拟器或真实游戏读档验证。

## 当前功能

- 四栏主界面：主页、追踪、工具、设置；底栏不再混入单个修改板块
- 主页展示游戏日期、累计游玩时间、存档中的真实外观参数，以及使用游戏像素素材的农场概览
- 追踪页按角色、人物外观、房屋、背包、财富进度、关系、技能职业、钱包能力、农场动物、配方和存档状态分板块只读查看
- 所有修改统一放在工具页；角色数值、人物外观、房屋、背包、财富进度、关系、技能职业、钱包能力、动物、配方与检查保存分别进入
- 未保存草稿可在各修改板块之间保留，最后从“检查与保存”统一写回
- 首次通过系统文件选择器授权外层 `Stardew Valley` 文件夹并自动发现全部存档，也可选择单个农场目录或同时选择主存档与 `SaveGameInfo`
- 编辑玩家、农场、日期、金钱、生命和体力；独立人物外观页提供原始/草稿对照、性别、发型、肤色和饰品选择库
- 编辑五项技能的等级、精确经验值和 5/10 级分支职业
- 编辑齐钻、齐币、累计收入、金色核桃、干草及矿洞进度，并只读汇总天气、任务和收藏统计
- 编辑 1.6 钱包特殊物品与能力；使用 `mailReceived` 标记写回并保留未知邮件标记
- 查看和编辑农场动物名称、亲密度、心情、饱食度与饲养天数，支持一键恢复全部最佳状态
- 编辑农舍升级等级，以及存档中已经存在的现代/旧版房间墙纸和地板字段；提供互动房间蓝图、标准样式库和逐项恢复
- 编辑、移动、复制、清空背包物品，并从 1.6 物品目录添加普通物品；598 个可安全添加物品均有中文名与图标，包含八种已确认的 1.6 字符串 ID 物品；支持完整分类浏览、收藏、最近添加和数量直接输入
- 修改 NPC 好感度以及安全的朋友/约会状态
- 解锁烹饪和制作配方；内置 231 条配方均显示简体中文名称、英文原名与分类图标
- 离线作物计算器：内置 47 种 1.6 作物，按游戏生长阶段规则计算成熟日、跨季收获、稻田加成、生长激素、职业、基础产量与收益
- 魔法地图：解析主存档 `Farm` 节点并按固定农场坐标系绘制作物、树木、物件、建筑、户外动物和大型资源；支持类型筛选、点选实体、全屏平移与 1–3 倍缩放
- 农场操作：给仍存活且未浇水的作物浇水，批量清理石块、杂草、枯枝，或只移除地图上点选的单个杂物；实时预览影响对象与坐标，确认保存时才写回
- 保存前显示差异，只写实际变化字段；自动备份两份文件，并在失败时回滚
- 新备份记录 SHA-256 完整性摘要，手动恢复与中断恢复前都会校验
- 保存最近使用目录的安全书签，支持恢复应用内备份
- 支持普通 XML 与 zlib 压缩存档
- 编辑页与地图提供固定检查入口，检查页显示全部差异并支持逐项撤销；地图操作列出具体对象与坐标
- 双文件事务按文件来源绑定；未知新进度先保留保护备份，发现冲突时由用户选择处理方式
- 备份页支持手动创建保护备份、校验和独立导出；原存档无法打开时也可导出已有有效备份
- 文件读取、解压、解析和写回交给串行后台服务；工作期间锁定草稿并显示处理状态
- 在既有 55 张资源基础上，从用户提供的 859 张游戏素材库中筛选接入 58 张：11 种农场动物、8 种果树、7 位补充 NPC、鱼塘，以及 31 张用于板块入口、技能、进度、钱包、地图和空状态的识别素材；当前共打包 113 张位图

## 运行

### GitHub 云端生成 IPA

已加入 `.github/workflows/build-ipa.yml`。本版成功构建记录为 [run 34190220247](https://github.com/ghb997/stardew-save-editor/actions/runs/34190220247)，生成 SHA-256 为 `96621789da9f3a1e6bf7030851cef22ad34b60b98c4f996bb0008ffaf2ef5d4c` 的未签名 iPhoneOS arm64 IPA。产物需自行签名后安装，详细操作见 [GITHUB_BUILD.md](GITHUB_BUILD.md)。

### Xcode 安装（推荐）

需要 macOS、Xcode 16 或更新版本（Swift 6）和 iOS 17 或更新版本。

1. 使用 Xcode 打开 `PelicanSaveEditor.xcodeproj`。工程已注册所有新增文件，无需先安装 XcodeGen。
2. 在 PelicanSaveEditor target 的 Signing & Capabilities 中选择自己的 Team。
3. 修改 Bundle Identifier（如有冲突），连接 iPhone 后运行。
4. 在应用中选择“我的 iPhone/Stardew Valley”目录；若其中有多个存档，再从应用列表中选择农场。也可以直接选择“农场名_数字”目录。

### Release 与侧载

在 Xcode 中选择 `Any iOS Device (arm64)` 和 Release 配置进行 Archive。需要侧载时，
使用个人证书签名导出的应用；覆盖已有安装时须保持原 Bundle Identifier 与签名 Team，
并使用更高的构建号。

普通自签不会获得跨应用沙箱权限，因此第一次仍必须使用系统文件选择器授权；应用会保存
安全书签，签名身份与 Bundle Identifier 不变且未重装时，后续可直接打开最近农场。

如果文件提供器不允许目录原位写入，可同时选择目录中的主存档文件与
`SaveGameInfo`；该模式直接更新已授权文件的内容，不创建同目录临时文件，适配自签环境的
文件级写入授权。仍然只读时，先把农场目录复制到“我的 iPhone”再操作。
自签游戏若连原位文件授权也无法返回，可使用“复制导入两个文件（备用）”；
该模式会在存档匣内保存独立副本，读取和修改都不会直接写回游戏存档。

> 修改前请退出游戏。任何存档编辑都有损坏风险；应用会自动备份，但仍建议额外复制一份原始农场目录。

## 当前边界

- 面向游戏 1.6.x 存档；其他版本会拒绝打开
- 仅允许从目录新增能安全构造的标准 Object；工具、任务物品和未知模组物品保持只读
- 友情状态只开放“朋友/约会”，婚姻、订婚、离婚等关系只读
- 房屋页只修改存档中已有的农舍等级、`appliedWallpaper`/`appliedFloor` 或旧版墙纸地板字段；不会猜测未知房间，也不会移动家具或改写容器内容
- 魔法地图只移除可识别的散落杂物；宝箱、机器、家具、建筑、大型资源块、活树和作物不会被点选删除
- XML 未知字段与属性会保留，但格式化空白不保证逐字节一致
- 任务、收藏统计只读；暂未提供社区中心、建筑、家具或剧情事件编辑
- 当前编辑主玩家；未提供联机农场中其他玩家的选择器。应用退出后的未保存草稿恢复仍是后续功能
- 白/棕/蓝鸡使用游戏内幼年物种示意，不表示存档实际年龄；虚空鸡、金鸡、恐龙和肤色色板仍无可靠素材，相关位置明确显示无预览。发型与饰品是独立图层预览，不是完整角色合成
- 地图使用真实坐标和参考网格；没有复原各类农场的完整地形。建筑仅显示已准确匹配的贴图，升级版本不借用基础建筑外观

## 数据与计算依据

- 内置作物目录是从 [`chiefpansancolt/stardew-valley-data`](https://github.com/chiefpansancolt/stardew-valley-data) 裁剪的纯数据子集，并按 1.6 游戏数据校正阶段天数、随机额外产物与种子价格。
- 生长加速和作物字段含义按 [Stardew Valley Wiki 的 1.6 作物数据说明](https://wiki.stardewvalley.net/Modding%3ACrop_data) 与 [Speed-Gro 规则](https://wiki.stardewvalley.net/Speed-Gro) 实现。
- 中文物品及配方名称按 [Stardew Valley 中文维基烹饪表](https://zh.stardewvalleywiki.com/%E7%83%B9%E9%A5%AA) 与 [中文物品名称模块](https://zh.stardewvalleywiki.com/%E6%A8%A1%E5%9D%97%3AItems/zh/id/name) 整理；未知模组内容保留原名。
- 板块入口、固定编辑顶栏、技能/进度字段、地图操作、界面题图、应用图标与背包物品图标均来自游戏像素素材，不使用 AI 生成图片；入口图只说明当前功能，不代表存档已经获得对应物品。人物页面只显示存档解析出的真实字段，地图实体位置仍以存档实际坐标为准。
